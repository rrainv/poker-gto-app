# Hand input (reconstruction) design interview (owner, from 2026-10-20)

M2 feature. Builds on NORTH_STAR §7.5 (reconstruct real hands; bet-size presets; "everyone else folds"; partial reconstruction with labelled estimates, never invented; money or bb input; phone-note paste; attach hands to a game night) and the Hand mockup https://claude.ai/artifact/KWaXJUnCPCE6rsMVcT2aHy.

| # | Topic | Decision | Date |
|---|---|---|---|
| HAND-01 | Entry flow | **A, table-first, is the main flow:** click on the table / action bar (seat to act highlighted, presets, smart skips). **Its result is kept and shown as B:** the history rail is the data view of what you entered ("you input actions, the rail displays your input through data"), editable row by row with everything after re-checked. **C, question-led, exists only as a beginner-friendly option** (owner: not as a main use). More strengths to combine were proposed (see HAND-02). | 2026-10-20 |
| HAND-02 | Strengths to combine | **All eight adopted**, in priority order: (1) typed commands in the action bar (`r9`, `c`, `f`, `AhKd`) alongside the mouse; (2) smart next step; (3) live facts in the rail while entering (pot, to call, effective stack, SPR); (4) edit any row, everything after re-checked by the rules engine, conflicts highlighted with a reason, never silently changed; (5) "about" amounts; (6) game night prefill (names, blinds, approximate stacks); (7) money or bb, both shown, stored exactly in bb; (8) one click onward (Review, Replay, Save, Send to Equity). **Owner refinements:** smart next step must **suggest, not assume**: offer "folds to ___" with the target seat choosable, and keep in mind a heavier **"table brush"** (sweep several seats as folded / called etc. in one gesture; later). "About" amounts must be **easily adjustable**: no assumed value; show quick options to play with (e.g. a few nearby sizes, a range like 8–12 bb, or "unknown") that the user picks from and can change any time. | 2026-10-20 |
| HAND-03 | Unknowns and gaps | **A + B:** every value (cards, amounts, stacks) is exact, about, or unknown (unknown cards = face-down backs); **gap rows** record forgotten stretches with what is known (who was in, roughly the pot after). Riverline invents nothing. **Owner's condition: only worth it if the maths and advice adjust correctly and stay useful.** So: uncertainty propagates through the engine (estimates labelled downstream); analysis runs only where inputs support it; where a gap makes advice meaningless, say Unavailable **with the reason and what would unlock it** (e.g. "add the turn bet size to analyse this river decision"); acceptance needs golden partial-hand tests proving the advice on partial hands is correct and useful, not just labelled. | 2026-10-20 |
| HAND-04 | Capturing a hand at the game | **B is the main path, with a proper format:** open the app → copy the capture format (or open the in-app capture editor with syntax hints) → write the hand in that syntax → Riverline parses and analyses. If the syntax is off, Riverline **makes guesses and always shows them** (each guess labelled, one tap to correct). The hand saves with gaps (HAND-03), attached to the game night, and is completed later where convenient. **A (full entry on the phone) also exists**, done properly even if returns are smaller. **C (free-text phone-note paste) stays as a backup.** Owner: this raises the need to start mobile app design soon. | 2026-10-20 |
| HAND-05 | End of hand | **C: result card + one instant takeaway line.** Card: winner(s), hand names, best five lifted on the table (approved showdown motion), net per player in bb (and money for game nights), side/split pots spelled out, mucked/unseen hands as face-down backs ("not shown", never guessed), "result unknown" allowed without touching the ledger, one-click Review / Replay / Save / Equity. Takeaway: one line from Review (biggest decision, luck), only when the known information supports it; otherwise it says what's missing. **Owner: the one-line summary must be designed carefully** (it compresses a whole hand; must not overstate or mislead); **all raw data stays available**, since Riverline analyses everything anyway. | 2026-10-20 |
| HAND-06 | Capture options (proposal) | https://claude.ai/artifact/X1HazzWjjqcuqApqCY6SRy: **1 · Tap** (position, two cards from a deck, actions tapped in order, rough pot, result; unknowns stay unknown), **2 · Short notes** (one line per street: `BTN AhKd 100` / `pre: hj r3, me 3b10, hj c` / `flop Ks8h4h: …`; codes f x c b r 3b 4b ai; `?` for unsure; a live reader shows what it understood and lists every guess with a Fix button), **3 · Free text** (backup; extracts what it can and asks). Manager suggestion: Tap as the phone default, Short notes for typists, Free text as backup. Awaiting owner choice. | 2026-10-22 |
| HAND-07 | Capture choice | **Tap is the default on the phone** ("the buttons feel best"); **Short notes stay for precision**, and the same short-notes syntax should also work **in table reconstruction on the PC** (typed into Hand alongside clicks; links to HAND-02's typed commands). Free text stays as the backup. | 2026-10-22 |
